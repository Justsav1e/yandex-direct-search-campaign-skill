# Yandex Direct Campaign Builder

Универсальный Agent Skill для системного создания **поисковых рекламных кампаний в Яндекс Директе**. Вместо разовой генерации списка ключей skill задаёт воспроизводимый исследовательский процесс: от понимания бизнеса и структуры посадочных до Wordstat, семантики, минус-слов, объявлений, аналитики, запуска и последующей оптимизации по реальным поисковым запросам.

> **Область применения: только Поиск.** Этот репозиторий не описывает методологию для РСЯ, товарных кампаний и фидов, смарт-баннеров, медийной рекламы, видеорекламы и других непоисковых форматов Яндекс Директа.

## Что умеет skill

Skill покрывает полный цикл работы с поисковой рекламой:

- выяснение того, что именно продаёт бизнес и что он не продаёт;
- анализ текущего сайта, посадочных страниц и структуры услуг;
- построение архитектуры кампаний и групп по поисковым интентам;
- исследование спроса через Яндекс Wordstat;
- работу с «Топами запросов» и «Похожими запросами»;
- итерационный semantic research через diverge → converge;
- формирование компактного ядра ключевых фраз;
- отдельную работу с локальными минус-словами конкретного ключа;
- формирование минус-фраз на уровне группы и кампании;
- безопасную работу с операторами Яндекс Директа;
- настройку поискового автотаргетинга;
- brainstorm и converge заголовков и текстов объявлений;
- работу с посадочными URL и параметрами отслеживания;
- ручные и автоматические стратегии на Поиске;
- проверку требований модерации;
- Яндекс Метрику и контроль целей;
- SEO/CRO readiness посадочной перед запуском;
- launch gate перед включением кампании;
- оптимизацию по Search Terms после запуска;
- сохранение состояния кампании между сессиями и агентами.

## Дополнительные reasoning skills

Workflow специально рассчитан на совместное использование с двумя универсальными reasoning skills:

- [`brainstorm-diverge-converge`](https://github.com/lyndonkl/claude/blob/main/skills/brainstorm-diverge-converge/SKILL.md) — для широкого поиска смысловых направлений, кластеризации и последующего сужения. Используется при исследовании семантики и brainstorm объявлений.
- [`First Principles Thinking`](https://github.com/awesome-skills/first-principles-skill/blob/main/SKILL.md) — для разложения задачи до базовых фактов и проверки исходных предположений. Используется перед решениями о структуре кампаний, групп и посадочных страниц.

Это **рекомендуемые companion skills, а не обязательные зависимости**. Если агент умеет подключать другие skills, он должен использовать их в соответствующих фазах. Если нет — в `SKILL.md` уже описан эквивалентный fallback-процесс.

## Зачем это нужно

Работа с Яндекс Директом чувствительна к мелким формулировкам и настройкам. Кампания может выглядеть законченной, но при этом быть методологически неправильной, например если:

- в одной группе смешаны разные поисковые интенты;
- Wordstat исследован поверхностно;
- семантика расширялась простыми перестановками слов;
- одиночное минус-слово случайно отрезает коммерческий запрос;
- перепутаны минус-слова ключа и минус-фразы группы;
- забыта семантика операторов;
- посадочная не соответствует конкретному поисковому интенту;
- UTM-параметры конфликтуют с параметрами состояния посадочной;
- агент забывает решение, принятое несколько десятков сообщений назад;
- настройки кампании строятся на устаревшем поведении Директа;
- новая посадочная создаётся раньше, чем данные показали, что она действительно нужна.

Этот skill превращает такие риски в обязательные checkpoints.

## Основной workflow

```text
Факты о бизнесе
  -> архитектура кампании
  -> готовность посадочных и аналитики
  -> Wordstat, раунд 1
  -> semantic diverge
  -> Wordstat, раунд 2
  -> semantic converge
  -> ключевые фразы
  -> локальные минус-слова ключей
  -> минус-фразы группы/кампании
  -> поисковый автотаргетинг
  -> brainstorm объявлений
  -> converge объявлений
  -> URL и аналитические параметры
  -> ставки / бюджет / гео / расписание
  -> проверка модерации
  -> launch gate
  -> анализ Search Terms
  -> обновление handoff/state
```

Главное здесь — **итерация**. Если во время анализа Wordstat находится действительно новый способ сформулировать продукт, агент не обязан угадывать. Он запрашивает у пользователя дополнительную выгрузку, получает CSV, анализирует её и возвращается к той же группе, сохраняя все предыдущие решения.

## Принципы работы

- **Сначала факты, потом структура.** Не создавать новые кампании, группы и посадочные без реальной причины.
- **Одна группа = один самостоятельный поисковый интент.** Не один ключ и не одна карточка товара.
- **Wordstat исследуется итерационно.** Топы + Похожие → diverge → дополнительный Wordstat при необходимости → converge.
- **Не размножать перестановки слов.** Ищутся действительно разные способы, которыми пользователь концептуализирует продукт.
- **Минусы имеют область действия.** Минус-слово конкретного ключа, минус-фразы группы и кампании решают разные задачи.
- **Операторы требуют буквальной точности.** Нельзя полагаться на «примерно помню».
- **`[]` используются для фиксации порядка слов.**
- **`+` используется для фиксации стоп-слов.**
- В skill используется консервативное правило **не записывать `+` внутри `[]`**; если нужен фиксированный порядок, используется форма с квадратными скобками без `+`.
- **Актуальная документация Яндекса важнее памяти агента.** Перед решениями, зависящими от текущего поведения интерфейса и системы, агент обязан заново проверить официальные источники.
- **Состояние кампании — часть результата.** URL, ставки, цели, временные решения, отклонённые гипотезы и незакрытые кандидаты должны сохраняться в handoff/state ledger.
- **Не переделывать сайт раньше данных.** Существующие страницы или intent-aware состояния можно использовать, пока реальные данные не покажут необходимость отдельной посадочной.
- **После запуска главным источником истины становятся реальные Search Terms.**

## Точность контекста

Этот skill специально содержит правила против «забывания» деталей агентом.

При продолжении существующей работы агент обязан:

1. перечитать текущий контекст и handoff/state-файлы;
2. восстановить последние принятые настройки кампании;
3. восстановить список групп и их статус;
4. восстановить утверждённые URL, ставки, аналитику, минусы и ограничения;
5. отдельно сохранить кандидатов, которые ещё не были окончательно приняты или отклонены;
6. не менять старое решение молча;
7. при изменении решения указать, какое новое доказательство привело к пересмотру;
8. после значимого этапа обновить состояние проекта.

Для этого в репозитории есть отдельный протокол `references/state-ledger.md` и шаблон handoff.

## Проверка официальных источников Яндекса

Перед решениями, которые зависят от текущего поведения платформы, агент должен проверять актуальную официальную документацию Яндекса.

В частности, когда это относится к задаче, следует заново проверять:

- ЕПК и актуальные типы объявлений;
- стратегии и ручные ставки;
- ключевые фразы и семантическое соответствие;
- минус-слова и минус-фразы;
- операторы;
- автотаргетинг и его категории;
- иерархию URL-параметров на уровнях кампании, группы и объявления;
- ограничения заголовков и текстов;
- требования модерации;
- Wordstat: Топы, Похожие, операторы, регионы и устройства;
- Метрику, цели и UTM;
- Webmaster, canonical и региональность, если принимается решение по посадочной.

**Требование:** фактические утверждения о текущих правилах Яндекса должны сопровождаться ссылками на источники.

Локальные reference-файлы в репозитории — это checklist и snapshot, а не вечная истина.

## Установка

### Агенты с поддержкой Agent Skills

Скопируйте папку репозитория в директорию skills, которую использует ваш агент или harness.

`SKILL.md` следует открытому формату Agent Skills: YAML frontmatter + Markdown-инструкции, с дополнительными `references/`, `assets/`, `scripts/` и `evals/`.

У разных клиентов пути обнаружения skills отличаются, поэтому конкретный путь установки лучше брать из документации вашего агента.

### Агенты без нативной поддержки Skills

Workflow всё равно можно использовать:

1. Передайте `SKILL.md` в project context / system instructions агента.
2. Сделайте доступными файлы из `references/` и `assets/`.
3. Попросите агента поддерживать отдельный campaign handoff/state после каждого значимого этапа.
4. Дайте агенту web-доступ для проверки актуальной документации Яндекса.
5. Передавайте ему CSV-выгрузки Wordstat по мере запроса.

Специальный API конкретной модели для этого не требуется.

```text
Используй workflow Yandex Direct Campaign Builder.

Перед решениями заново проверь актуальную официальную документацию Яндекс Директа и Wordstat и ссылайся на источники.

Не создавай новые посадочные страницы раньше фактических данных.

Для каждой группы:
1. исследуй Wordstat Топы и Похожие;
2. проведи semantic diverge и найди действительно разные смысловые корни, а не перестановки слов;
3. при необходимости запроси второй раунд Wordstat;
4. проведи converge до компактного ядра;

6. отдельно проверь необходимость локальных минус-слов у конкретных ключей;

10. проверь URL, аналитику и launch gate.

Сохраняй все подтверждённые решения, временные обходные решения, отклонённые варианты и незакрытые кандидаты в campaign handoff. Не теряй детали при длинном диалоге и не меняй ранее принятое решение без объяснения новой причины.
```

## Workflow файлов Wordstat

Пользователь или оператор выгружает CSV из Wordstat и передаёт их агенту по мере запроса.

Перед анализом агент должен определить для каждого файла:

- исходный seed query;
- тип выдачи: Топы или Похожие;
- период;
- регион;
- фильтр устройств;
- количество строк;
- связь с конкретной рекламной группой и исследовательской гипотезой.

`scripts/wordstat_index.py` — необязательный вспомогательный скрипт, который индексирует CSV-выгрузки Wordstat и формирует JSON-карту файлов.

Пример:

```bash
python scripts/wordstat_index.py ./wordstat-exports > wordstat-index.json
```

Skill не зависит от скрипта: агент может анализировать CSV напрямую.

## State и handoff

Skill рассматривает память как инженерную задачу, а не как надежду на то, что модель «сама не забудет».

Handoff/state должен содержать как минимум:

- подтверждённые факты о бизнесе;
- настройки кампании;
- географию;
- стратегию и ставки;
- расписание;
- карту посадочных URL;
- аналитические цели;
- реестр групп и их статусы;
- Wordstat evidence;
- принятые ключевые фразы;
- локальные минус-слова;
- минус-фразы группы и кампании;
- настройки автотаргетинга;
- принятые объявления;
- временные обходные решения;
- кандидатов, которые ещё исследуются;
- отклонённые решения и причины отклонения;
- точное следующее действие.

Это позволяет продолжать работу через десятки сообщений, новые сессии или даже другим AI-агентом без потери контекста.

## Только поисковые кампании

Этот skill **не следует использовать как готовую методологию** для:

- РСЯ;
- ретаргетинга в сетях;
- товарных кампаний;
- товарных фидов;
- ecommerce/product ads;
- смарт-баннеров;
- медийной рекламы;
- видеорекламы;
- других форматов Яндекс Директа, где требуется отдельная логика креативов, аудиторий, ставок и оптимизации.

Если задача выходит за рамки Поиска, агент должен прямо сказать, что это находится вне scope этого skill, а не переносить поисковую методологию на другой формат без проверки.

## Актуальные правила Яндекса

`references/current-yandex-rules.md` содержит последний проверенный snapshot важных правил, однако он **не заменяет live-проверку документации**.

Яндекс Директ и его интерфейс меняются. Поэтому skill требует повторно проверять официальный источник перед решениями, зависящими от:

- текущих типов объявлений;
- доступных стратегий;
- лимитов;
- операторов;
- поведения автотаргетинга;
- URL-параметров;
- модерации;
- аналитических возможностей.
